# V4.0 Step 4a: The Remaining Arms Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the four arms the registered run needs beyond step 3's eight, each producing a self-verified `summary.json` from a one-cell CLI:
- `hold_btc_trend` (v4-d20);
- `v4_btc200_shorts` and `v4_confirm3` (v4-d22);
- `v3_as_built`.

Also build V3's input pack on GitHub, pinned to V3.1's registered digest.

**Architecture:** Step 4 of the spec is split in two plans and PRs, both before step 5's registration (v4-d15):
- **4a (this plan): the arms.** At the end, all 12 arms (48 cells) can each be run and verified on their own.
- **4b: the pipeline and the verdict step.** The comparisons, the resumable verdict, the run summary, the registered-run workflow and the synthetic rehearsal.

The arms fit the code as follows:
- The two new trend arms are `v4` family arms: two new `ArmSpec` fields, read in `_V4Cell._view` and `_feed` (`run.py`).
- `hold_btc_trend` is a `hold` family branch in `hold.py`.
- `v3_as_built` is a new `v3` family. A new module runs V3's frozen selector through V3.1's reviewed runner (`combined.baseline_v3`), unchanged, and turns V3's own marks into V4-format records and a V4-format summary.

**Tech Stack:** Python 3.12, standard library only, pytest. No new dependency. GitHub Actions for everything that reads real data.

**Spec:** `docs/superpowers/specs/2026-10-17-v4-design.md`: "Versions in the run" (the arm table, the hold comparisons, `hold_btc_trend`, `v3_as_built`), "Pass rule" (the common measure the summaries must support), "Reports", "Engineering", "Verification", "Delivery" item 4. Owner decisions v4-d20 (`hold_btc_trend`, reported only) and v4-d22 (2026-10-23, option B: two reported-only arms, defined before their results are seen; their first real results come in the registered run).

**Rulings this plan makes** (the spec and v4-d22 leave these open; each is cheap to change before registration):
- **R1, the two arms' exact rules:**
  - `v4_btc200_shorts`: at each 00:00 decision, shorts are allowed only while BTCUSDT's latest daily reading (the last completed daily bar at or before the decided day) has its slow vote at -1, i.e. close below its SMA(200). Above, an exact tie, warming, or no BTC bar yet all mean not allowed. While not allowed, every coin's signal is clamped to `max(signal, 0)` before sizing, as an ineligible coin's is. A held short therefore closes at the next fill, and longs are unchanged.
  - `v4_confirm3`: a reading's direction is the sign of its raw `s` (+1, 0 or -1). Per coin, the arm keeps the effective signal `e` (0 before any reading), the last direction and its run of consecutive readings. On each new reading, the run grows if the direction repeats, else it restarts at 1. If the reading's direction equals `e`'s, `e` becomes the reading's `s` at once (a size change within one direction follows at once). Otherwise `e` changes to the reading's `s` only when the run reaches 3. Until then it keeps its value. A no-bar day adds no reading. A universe exit and a dead market still zero the signal at once.
  - Both arms use the main settings otherwise: 40% volatility target, main lookbacks, long and short.
- **R2:** `hold_btc_trend` uses the same slow vote. It is invested iff the vote is +1, starts in cash, and makes an order only when that state changes. A no-bar day keeps the state. Its orders and lifecycles use the source and exit reason `signal`.
- **R3, `v3_as_built`:**
  - **Window:** 2021-07-01 00:00 UTC (V3's first out-of-sample quarter) to the open of 2024-12-31 23:00, with V3's terminal mark at 2025-01-01 00:00 as its final equity.
  - **Picks:** computed once per run with `selector_picks` (10,000 USDT, V3's size multiple 2, base cost), written canonically and pinned by SHA-256. Every v3 cell requires that pin.
  - **Capital:** 1,000 USDT runs through `v3_capital`, which `replay_v3_baseline` applies with the disclosure `v3_capital_adapter_sets_only_starting_capital`.
  - **Open marks:** an hour's open mark is V3's `open` native mark. It is complete iff every one of V3's 10 coins has its hourly bar that hour. This is conservative: V3 holds a subset.
  - **Outcome:** status None maps to `complete`; `liquidation` maps to `liquidated`, with the stop at its mark's hour; every other V3 stop maps to `engine_error`, type `V3Stop` and message the status. So a V3 stop is incomplete, never a pass.
  - **Summary `data`:** `{"v3_pack_sha256": ..., "picks_sha256": ...}`. `equity_2025` and `final_after_close` are null.
- **R4:** the V3 input pack is built on GitHub with V3's own frozen loader and assembly (`scripts/v31_v3_pack.build_v3_pack`). It must equal V3.1's registered `v3_pack_sha256`, `8a4780009bfe580995396b60fd30e52bbc21888a470e49eedb84910087a55dee` (`config/v3_1_run_manifest.json`), or nothing is uploaded. This proves the input is the one V3 was run on.
- **R5, timing evidence:**
  - the 8 step-3 arms: the diagnostic run (cells run 40001349425, 2026-10-23), at most 175 s and 470 MB a cell;
  - `v3_as_built`: V3.1's run 38703911852, with picks 2 h 32 min and a V3 cell 5-15 min. Task 7's first dispatch measures it again.
  - The three new V4/hold arms are cheap variants of measured arms. They get no real-data run before registration (v4-d22).

## Review Focus

1. **BTC's own gaps:** a decision day with no BTC bar, BTC masked hours, or BTC warming up. The filter and `hold_btc_trend` must keep the last reading (or "not allowed" / cash before any), never read a later bar. Tested in Tasks 2 and 4.
2. **Catch-up feeding in `v4_confirm3`:** a coin's first decision, or its return to the universe, feeds many bars at once. Each bar is one reading for the run, and a no-bar day is none. Tested in Task 3.
3. **`v3_as_built` at 1,000 USDT and at doubled costs:** the adapter disclosure is kept, and V3's own stops map as R3 says. Tested in Task 6.
4. **The V3 fetch:** an entry with status `missing` is skipped as V3's loader expects; a changed upstream archive fails its SHA-256 and nothing is built; a pack whose pin differs from R4's is never uploaded. Tested in Task 5.
5. **Mislabelled cells:** a v3 summary for another capital, cost, window, pack or picks fails its own verification, and a `v4_cell.py` run of `v3_as_built` on V4 packs is refused. Tested in Tasks 1 and 6.
