# V3.1 Run Driver Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Run the registered V3.1 experiment once on GitHub Actions from pinned data and keep every result: prepare packs, run one job per cell, aggregate with `evaluate`.

**Architecture:**
- A prepare job fetches and verifies archives through the existing guarded transports. It decodes them into deterministic per-window input packs, which include a precomputed per-hour flow schedule in place of minute bars.
- One run job per registered cell passes an execution gate, replays the cell and writes a cell artifact.
- An aggregate job evaluates every cell, renders the pages and writes the evidence bundles.
- A smoke mode runs the same path on synthetic packs.

**Tech Stack:** Python 3.12, standard library only (Decimal, Fraction, json, gzip, hashlib), pytest, GitHub Actions.

**Spec:** `docs/superpowers/specs/2026-10-12-v3-1-run-driver-design.md`. Inputs: `docs/superpowers/specs/2026-10-11-v3-1-registration-proposal.md`, `docs/reviews/2026-10-11-claude-v3-1-conformance.md` (registration checklist), `docs/V3_1_SOURCE_INVENTORY.md`.

## Global Constraints

- **Code location:** driver code lives in `src/crypto_grid_bot/combined/driver/` (pure, testable) and `scripts/v31_driver.py` (CLI and network glue). Nothing under `simulation/`, `trend/`, `strategy/` or `backtest/` changes.
- **No 2025+ data:** nothing at or after `1_735_689_600_000` ms is requested, opened, decoded or read. Every input path refuses it, and the workflow fails if any `-2025-`.. file exists.
- **Network:** only in the prepare job. It goes only to data.binance.vision through `backtest.dataset.archive_get` or `scripts/fetch_v3_data.V3Transport`, and every archive is verified against its committed SHA-256. Tests block the network and use a fake host.
- **Numbers:** money, price and quantity math use `Decimal`/`Fraction`, never `float`. Pack and outcome serialization write Decimals as strings.
- **Determinism:** the same inputs give byte-identical packs and artifacts. Use sorted keys, fixed separators, gzip with `mtime=0`, and no timestamps inside packs.
- **No retries:** every attempt is recorded and none is retried. Each artifact is written once, with an exclusive create.
- **Process:** test first, one commit per task, messages ending `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Full gate `python -m pytest -q tests/test_combined_*.py tests/test_v31_*.py` before each commit, plus ruff check/format and mypy on touched files.

## Review Focus

- **A minute source missing its final in-window minute:** the pack build refuses the window with the coin and minute named. It must not produce minute baselines that are incomplete later. Task 5.
- **An archive whose bytes differ from the manifest SHA-256 (corrupt or changed upstream):** prepare stops before decoding and names the path. It is never cached as good. Task 4.
- **A cell artifact from a different code commit or pack, mixed into aggregation:** aggregate refuses it, since acceptance must not combine runs of different inputs. Task 9.
- **A registration cell list that omits a required cell:** the registration check refuses it before any run; `evaluate` would otherwise report incomplete only after hours of compute. Task 6.
- **A rerun of the workflow on the same registration:** it never overwrites earlier artifacts. Artifact names carry the run attempt, and aggregation refuses duplicate cells. Tasks 9 and 10.

### Task 5: Deterministic input packs and skipped hours

**Files:**
- Create: `src/crypto_grid_bot/combined/driver/packs.py`
- Test: `tests/test_v31_packs.py`

**Interfaces:**
- Consumes: the Task 2 decoded months, the Task 1 `FlowSchedule` and the Task 3 `VenueRules`.
- Produces: `CoinInputs`, with:
  - `symbol`;
  - `spot_hourly` and `futures_hourly` (`tuple[Kline,...]`; futures is `()` when the window has no futures inputs);
  - `daily` (`assessment.daily_bars(spot_hourly)`);
  - `funding: tuple[FundingRecord,...]`, including the latest record published before the window;
  - `spot_rules`, `futures_rules: VenueRules | None`, `flow: FlowSchedule`.
- Produces: `WindowPack`, with `window_id`, `start_ms`, `end_ms`, `coins: tuple[CoinInputs,...]` (sorted by symbol), `skipped_hours: tuple[int,...]` and `sources: tuple[tuple[str,str],...]` (manifest name and SHA-256).
- Produces: `derive_skipped_hours(...) -> tuple[int, ...]`. The result is the union of every coin's missing spot and futures hours and every hour whose opening minute is missing, restricted to `start < h < end - 1h`.
- Produces: `check_window(pack) -> None`, which raises `ValueError` in each of these cases:
  - the first or last window hour would need skipping;
  - any minute source lacks the final in-window minute (`end - 60_000`);
  - any spot month in the window or its warm-up has more than 17% of its hours missing;
  - a futures window coin has no funding record usable at the start.
- Produces: `write_pack(pack, path) -> str`, which writes gzip JSON (sorted keys, mtime 0, Decimals as strings) and returns its SHA-256. Also `read_pack(path, expected_sha256) -> WindowPack`.
