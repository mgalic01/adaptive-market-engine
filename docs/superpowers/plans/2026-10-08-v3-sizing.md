# V3 volatility sizing implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans. Track tests and rulings in the local ledger.

**Goal:** Turn the frozen V3 signals into deterministic volatility-weighted portfolio targets.

**Architecture:** Pure functions in `trend/sizing.py` produce consecutive-day returns and auditable portfolio weights. Execution quantities, account events and WFO consume these targets in later modules; this module does not trade.

**Tech Stack:** Python standard-library Decimal; pytest. No dependencies.

**Spec:** `docs/EXPERIMENT_SPEC_V3.md` sections 2 and 5 steps 1–3.

## Global constraints

- Frozen experiment: no changed parameters or additional candidate strategies.
- Decimal precision 60, ROUND_HALF_EVEN; sample statistics with n−1.
- Historical inputs through 2024-12; no network or market archive reads.
- Last 60 returns for individual volatility; last 60 UTC days and at least 40 common observations for covariance.
- m in 1,2,3; volatility target 0.20*m, per-coin cap 0.10*m, gross cap 0.80*m.

## Review focus

- Calendar gaps must never become multi-day returns (task 1).
- Future samples must not influence an earlier decision (task 2).
- Excluded and zero-signal coins must not shrink covariance overlap (task 2).
- Singular covariance requires no inverse; zero portfolio variance goes flat (task 2).
- Ambient Decimal settings and mapping insertion order must not affect results (both tasks).

## Task 1: Consecutive-day returns

Files: create `src/crypto_grid_bot/trend/sizing.py`, `tests/test_trend_sizing.py`.
Produces: frozen `DailyReturn(day_ms: int, value: Decimal)` and `daily_returns(bars: Sequence[Kline]) -> tuple[DailyReturn, ...]`.
The timestamp names the later day's close. Validate sorted UTC days and positive finite closes before arithmetic. Return C[d]/C[d-1]-1 only when timestamps differ by exactly 86400000ms.

- [ ] Add tests for 100→110, a missing day, 110→99, duplicate/unordered dates and nonpositive closes.
- [ ] Run tests; require failure because API is absent.
- [ ] Implement under a fresh 60-digit Decimal context.
- [ ] Verify exact 0.1 and -0.1 returns, gap omission and hostile ambient context.
- [ ] Commit.

## Task 2: Volatility and covariance weights

Consumes DailyReturn sequences, keyed by coin, and signals from SignalPoint.rule.
Produces `size_portfolio(signals: Mapping[str, Decimal], returns: Mapping[str, Sequence[DailyReturn]], day_ms: int, *, excluded: frozenset[str] = frozenset(), multiple: int = 2) -> SizingResult`.
SizingResult exposes weights, raw weights, individual annual volatility, common days, estimated volatility and flat reason. Return a weight for every supplied signal key.

- [ ] Add tests for 59/60 returns, zero volatility, exclusion, 39/40 overlap, calendar cutoffs, zero/singular covariance, caps and all three multiples.
- [ ] Run and observe absent API failure.
- [ ] Implement written formula order, sorted symbol/date iteration, no matrix inversion. Reject negative computed variance rather than silently tuning an epsilon. Filter future observations before sizing.
- [ ] Verify hand-computable correlated/offset return fixtures and prefix independence; add invalid inputs and hostile context checks.
- [ ] Run focused tests and static checks; commit. Request whole-branch independent review and exact-head external review, with full CI before merge.
