# V3 continuous signals implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox syntax for tracking.

**Goal:** Implement the six frozen V3 daily signal rules and their long-only twins.

**Architecture:** A per-coin state object consumes chronologically ordered eligible
spot daily bars once. Immutable output points expose all twelve rule signals. A
batch wrapper produces the same series; downstream runs slice it without resetting
recursive state. Missing days are absent updates, not synthetic zero-price bars.

**Tech Stack:** Python standard library, existing Kline, Decimal.

**Spec:** docs/EXPERIMENT_SPEC_V3.md sections2,4 and precision paragraph in5.

## Global constraints

- No real data, network, strategy result, tuning or dispatch.
- All signal arithmetic uses Decimal precision60, ROUND_HALF_EVEN, written formula order.
- Fixed menu R1..R6,R1L..R6L; no added strategy family.
- No existing strategy module changes. Sizing/execution are subsequent batches.
- Inputs are unmasked UTC daily OHLC bars; invalid/duplicate/out-of-order inputs fail
  before state changes. Reserved dates remain outside the development input boundary.

## Review focus

- Strict equality at channel/band boundaries must not invent a breakout.
- Missing dates retain recursive state;365-day lookback is calendar-based with7-day tolerance.
- Supertrend seeds at bar11 using10 true ranges, not10bars.
- R6L clips the blend after averaging, not each constituent first.
- Ambient Decimal precision/rounding must not change any output.
