# V3 account primitives implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans, test-first with independent branch review.

**Goal:** Implement auditable futures fills, grouped funding, marks and terminal liquidation.
**Architecture:** Stateful account with immutable position/event records and pure mark snapshots. Wallet derives from chronological accumulated ledger totals in the spec's written order. The hourly event runner remains separate.
**Tech Stack:** Python Decimal and dataclasses; pytest.
**Spec:** `docs/EXPERIMENT_SPEC_V3.md` section6 wallet/fills/funding/liquidation and section8 accounting-failure treatment.

## Global constraints

Decimal60 ROUND_HALF_EVEN. Default capital10000 USDT. Fee/slippage each0.0005, doubled together only in cost stress. Futures notional never moves cash. No live routes, data reads, tuning or spec changes. Exact identity checks stay exact until the owner accepts the separate numerical proposal.

## Review focus

Long/short sign symmetry; weighted entries after adds/partial closes; same-time funding atomicity; invalid events leave state untouched; equality at liquidation threshold stops later mutation without simulated fills. Cover all with synthetic tests.

Records expose quantity, entry, fee, realized PnL, rates/payments, price and timestamp.

## Boundary

This class enforces valid primitives and terminal liquidation. Hourly open/fill/funding/adverse ordering, masked marks, delevering, deferred decisions, lifecycle analytics and WFO remain in the future event runner. Audit failure stops the experiment, not merely a candidate rule.
